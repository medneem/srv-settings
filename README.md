# srv-settings

Интерактивный Bash-инструмент для первоначальной настройки и последующего администрирования VPS/серверов Ubuntu.

> **Статус:** первая рабочая версия. Скрипты опубликованы, но интеграционные испытания на реальном Ubuntu VPS ещё не проводились. Прежде чем применять на production, проверьте на тестовой машине с доступом к консоли/VNC.

## Быстрый запуск

Запуск **одной командой** на сервере Ubuntu:

```bash
curl -fsSL https://raw.githubusercontent.com/medneem/srv-settings/main/bootstrap.sh | sudo bash
```

Стартовый `bootstrap.sh`:
1. Проверяет Ubuntu, права root и наличие терминала.
2. Скачивает файлы проекта из этого репозитория.
3. Запускает интерактивное меню `setup.sh` с вводом через `/dev/tty`.

Расположение файлов после установки — `/opt/srv-settings/`. Для повторного запуска меню:

```bash
sudo bash /opt/srv-settings/setup.sh
```

**Как работает интерактивный ввод через pipe?** Стартовый Bash-скрипт скачивается через stdin, затем `bootstrap.sh` запускает меню с вводом из `/dev/tty`. Поэтому можно вводить логин, пароль и порты непосредственно в SSH-терминале. При отсутствии интерактивного терминала запуск завершится ошибкой.

**Безопаснее перед запуском просмотреть код.** Вариант ниже загружает скрипт в файл и позволяет его изучить. При использовании pipe без `set -o pipefail` ошибка `curl` не всегда становится кодом выхода всей команды.

Для предварительного просмотра:

```bash
curl -fsSLo /tmp/srv-settings-bootstrap.sh https://raw.githubusercontent.com/medneem/srv-settings/main/bootstrap.sh
less /tmp/srv-settings-bootstrap.sh
sudo bash /tmp/srv-settings-bootstrap.sh
```

> Не запускайте команду на рабочем сервере, пока не изучены скрипты, а настройки SSH и firewall не проверены на тестовой VPS. Используйте консоль провайдера/VNC на случай потери SSH-доступа.

## Главное меню

```text
========== SERVER SETTINGS ==========

1. Полная первоначальная настройка
2. Управление портами TCP/UDP (UFW)
3. Настройка SSH
4. Управление пользователями и sudo
5. Настройка Fail2ban
6. Обновление системы
7. Диагностика и проверка состояния
8. Дополнительные настройки

0. Выход
=====================================
```

В режиме полной настройки мастер предлагает:
- имя нового пользователя и пароль (без вывода пароля на экран);
- добавление пользователя в группу `sudo`;
- порт SSH и разрешение/запрет входа по паролю;
- список открытых TCP-портов через запятую, например `80,443,1443`;
- список открытых UDP-портов через запятую, например `26,27,1053`;
- часовой пояс, синхронизацию времени и прочие параметры;
- настройку Fail2ban (`maxretry=3`, `findtime=30m`, `bantime=24h` в текущей версии).

## Возможности

- **Ubuntu:** поддерживаемые версии Ubuntu Server: **22.04 LTS, 24.04 LTS и 26.04 LTS**. Другие версии требуют отдельного подтверждения при запуске.
- **Система:** обновление пакетов, часовой пояс, NTP, базовые утилиты.
- **Пользователи:** создание пользователя, настройка sudo, управление доступом.
- **SSH:** отдельный конфиг в `sshd_config.d`, проверка `sshd -t`, учёт `ssh.socket` в Ubuntu 24.04/26.04.
- **UFW:** разрешение/удаление TCP/UDP-портов, просмотр правил, настройки логирования.
- **Fail2ban:** установка, настройка защиты SSH, проверка состояния, разблокировка IP и управление доверенными IPv4/IPv6-адресами и CIDR-подсетями (постоянные исключения `ignoreip` для jail `sshd`).
- **Docker (по желанию):** через «8. Дополнительные настройки» можно установить официальный Docker Engine, Compose и Buildx либо настроить зеркала Docker Hub для установленного Docker. При полной настройке сервера Docker не устанавливается.
- **Диагностика:** состояние SSH, UFW, Fail2ban, прослушиваемые порты и журналы.
- **Повторный запуск:** операции должны быть идемпотентными и не дублировать правила.

## Дополнительные настройки: Docker

Из главного меню выберите **8. Дополнительные настройки → 1. Docker (необязательно)**:

```text
DOCKER (необязательно)
1. Установить Docker Engine + Compose (официальный APT)
2. Настроить зеркала Docker Hub
3. Проверить состояние Docker
4. Показать daemon.json
0. Назад
```

Установка выполняется **только после явного подтверждения** и следует [официальной инструкции Docker для Ubuntu](https://docs.docker.com/engine/install/ubuntu/): ключ в `/etc/apt/keyrings/docker.asc`, отдельный Deb822-файл `/etc/apt/sources.list.d/docker.sources` c `Signed-By`, канал `stable`. Устанавливаются `docker-ce`, `docker-ce-cli`, `containerd.io`, `docker-buildx-plugin`, `docker-compose-plugin`. Поддерживаются Ubuntu 22.04 (jammy), 24.04 (noble) и 26.04 (resolute). Использования `get.docker.com` и установки Ubuntu `docker.io` нет.

При наличии конфликтующих пакетов (включая `docker.io`, `containerd` и `runc`) скрипт показывает полный список и **отдельно спрашивает** разрешение на их удаление. Удаление может остановить работающие контейнеры или другие приложения; не подтверждайте на рабочем сервере без проверки. Скрипт не удаляет каталоги `/var/lib/docker` и `/var/lib/containerd`. Файлы APT-репозитория сохраняются в резервной копии перед перезаписью; повторный запуск на уже работающем официальном Docker завершается без переустановки.

**Безопасность:** Docker публикует контейнерные порты так, что они могут обходить привычные ограничения UFW. Перед запуском контейнеров настройте политику доступа через `DOCKER-USER` или другие подходящие правила. Docker запускается от root; в группу `docker` скрипт пользователей автоматически **не добавляет**, потому что её членство даёт привилегии, эквивалентные root. Зеркала меняются отдельным пунктом с подтверждением и бэкапом `daemon.json`, а не автоматически при установке.

## Требования к безопасности

1. Перед изменением SSH сохранять резервную копию конфигурации и проверять её синтаксис.
2. Сначала разрешать новый SSH-порт в UFW, и только потом переключать SSH. Старый порт закрывать **после проверки нового подключения**.
3. При настройке удалённого сервера не полагаться исключительно на существующую SSH-сессию; предусмотреть безопасный откат.
4. Не включать `NOPASSWD: ALL` автоматически: только отдельной опцией и после подтверждения.
5. Для SSH предпочтителен вход по ключу; парольный вход — явный выбор пользователя.
6. Не перезаписывать существующие настройки SSH, UFW или Docker без проверки и резервной копии.
7. Учитывать, что опубликованные Docker-порты могут обходить обычную фильтрацию UFW; правила доступа к контейнерам требуют отдельного внимания.
8. Не сохранять введённые пароли в логах.

## Разработка

Репозиторий: https://github.com/medneem/srv-settings

Основные возможности: SSH, UFW, Fail2ban, пользователи и диагностика. GitHub Actions на Ubuntu 22.04/24.04/26.04 запускает три этапа: Bash-синтаксис и ShellCheck, тесты Bash-функций с подменой системных команд, Python-тесты Docker JSON и проверку запуска `curl | sudo bash` в псевдотерминале. Тесты не меняют настройки SSH/UFW систем CI. Системные настройки необходимо проверить на тестовом VPS перед использованием на рабочих серверах.

## Что важно знать перед запуском

- Смена SSH-порта запускает таймер автоматического отката на 5 минут через `systemd-run`: подтвердите успешное подключение из второго терминала. Старый порт UFW не удаляется автоматически.
- **Отключение входа root — только после проверки:** SSH-мастер выводит команду для копирования в другой терминал с **реальным логином и адресом сервера** (например, `ssh -p 22 admins@203.0.113.42`, где адрес иллюстративный). Для адреса используется `SSH_CONNECTION`/`SSH_CLIENT`; логин берётся из `SUDO_USER` либо из единственного пользователя группы `sudo`. Если логин или адрес нельзя однозначно определить, мастер не запрашивает адрес сервера: выводит ручной пример `ssh -p <порт> ПОЛЬЗОВАТЕЛЬ@АДРЕС_СЕРВЕРА`, а пользователь может продолжить только после отдельного подтверждения успешного входа во втором терминале. Проверьте, что вы подключаетесь именно по адресу, доступному с вашего компьютера, особенно если используется NAT или домен. После подключения проверьте `whoami` и `sudo -v && sudo id -u` (результат `0`). Если не проверяли, отвечайте **Enter/N** — вход root останется включённым. Не закрывайте первый SSH-сеанс; после смены SSH-порта мастер выведет отдельную команду с **новым портом**.
- В Ubuntu 24.04/26.04 учитываются `ssh.socket` и `systemctl daemon-reload`. После изменения порта необходима проверка реального нового SSH-подключения.
- **Ubuntu 26.04 LTS:** OpenSSH 10.2, systemd 259; на новых установках используется Chrony для синхронизации времени. Скрипт использует `timedatectl set-ntp true` и не заменяет Chrony на `systemd-timesyncd`.
- CI для Ubuntu 26.04 проверяет в том числе возможность установки `openssh-server`, `ufw`, `fail2ban`, `python3-systemd` и `rsyslog` в режиме симуляции APT. Работа firewall/SSH на реальном VPS этим тестом не подтверждается.
- Пароль пользователя вводится через `passwd`, а не аргументом командной строки.
- **Docker находится только в разделе «8. Дополнительные настройки».** Пункт 1 («Полная первоначальная настройка») не ставит Docker и не требует его наличия. Автоматические резервные копии SSH и важных конфигураций сохранены, хотя отдельный пункт резервного копирования убран из главного меню.
- Bash-синтаксис, ShellCheck, тесты функций UFW/портов, установки Docker с подменой системных команд, Docker JSON и интерактивного запуска bootstrap через pipe запускаются в GitHub Actions для Ubuntu 22.04/24.04/26.04. Это не заменяет интеграционные тесты Docker/SSH/UFW на VPS.

## Доверенные IP-адреса в Fail2ban

В главном меню выберите **5. Настройка Fail2ban**. Для SSH jail доступны:

- **6. Добавить IP/CIDR в исключения SSH** — ввод через запятую: `192.168.1.10, 10.10.0.0/16, 2001:db8::5`.
- **7. Удалить IP/CIDR из исключений SSH**.
- **8. Показать исключения SSH** (сохранённые и активные).

После первоначальной настройки Fail2ban мастер также предлагает добавить доверенные адреса. Список хранится в `/etc/fail2ban/jail.d/95-srv-settings-ignore.local` и сохраняется при повторной настройке через меню.

Входные значения проверяются через Python `ipaddress`. Адреса IPv4, IPv6 и подсети CIDR поддерживаются; некорректные значения, пустые элементы списка и сети `/0` отклоняются. Повторы удаляются. Настройки проверяются `fail2ban-client -t` до перезагрузки SSH jail; при ошибке прежний файл восстанавливается.

**Важно:** исключения действуют только для jail `sshd`, а не глобально для всех jail. Управляемый `ignoreip` может переопределить ранее заданный `ignoreip` для SSH в других конфигурационных файлах: перед подтверждением программа показывает действующий список — его нужно учесть. Добавление исключения не снимает уже действующий бан: для этого используйте пункт **4. Разбанить IP**. Исключения не добавляются автоматически в UFW и не обходят другие firewall-правила.


## Если загружается старое меню или не принимается настройка SSH

Загрузчик через GitHub API получает точный SHA последнего коммита `main`, затем скачивает архив по неизменяемому SHA. Установленная версия печатается при запуске и сохраняется в `/opt/srv-settings/.installed-commit`. Для проверки: `cat /opt/srv-settings/.installed-commit` и `grep -n "Дополнительные настройки" /opt/srv-settings/setup.sh` — раздел должен находиться под пунктом **8**. Для загрузки используется GitHub API; если API недоступен или исчерпан лимит анонимных запросов, загрузчик остановится, не подменяя файлы устаревшим архивом.

Для `PasswordAuthentication` допустимы `yes` и `no` (регистр не важен, пробелы и завершающий CRLF отбрасываются). Неправильный или повреждённый ввод теперь приводит к повторному запросу с диагностикой полученного значения, а не к выходу в меню. Перед перезапуском SSH проверяется синтаксис конфигурации, новый порт сначала открывается в UFW, а подтверждение подключения выполняется из второго терминала.

В Ubuntu 22.04 `ssh.socket` может быть неактивным, когда работает `ssh.service`. Меню диагностики SSH показывает состояние обеих служб.
