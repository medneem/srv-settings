# srv-settings

Интерактивный инструмент для настройки и управления Ubuntu Server **22.04, 24.04 и 26.04 LTS**.

## Установка и запуск

Подключитесь к серверу по SSH и выполните:

```bash
curl -fsSL https://raw.githubusercontent.com/medneem/srv-settings/main/bootstrap.sh | sudo bash
```

Установщик загрузит актуальную версию в `/opt/srv-settings/` и откроет меню. Чтобы запустить его повторно:

```bash
sudo bash /opt/srv-settings/setup.sh
```

## Главное меню

```text
========== SERVER SETTINGS ==========
1. Полная первоначальная настройка
2. Управление TCP/UDP-портами (UFW)
3. Настройка SSH
4. Управление пользователями и sudo
5. Настройка Fail2ban
6. Обновление системы / время
7. Диагностика
8. Дополнительные настройки
9. Перезагрузка сервера
0. Выход
=====================================
```

**1. Полная первоначальная настройка** — последовательно создаёт резервные копии, предлагает настроить систему и время, пользователей и sudo, SSH, UFW и Fail2ban. Каждый этап требует подтверждения.

**2. UFW** — разрешение и удаление TCP/UDP-портов, просмотр правил, управление логированием. После подтверждённого переноса SSH с порта 22 на другой порт в этом же запуске мастер может предложить удалить старое правило `22/tcp`. Без отдельного подтверждения оно не удаляется.

**3. SSH** — изменение порта, парольной аутентификации и доступа root. Новый порт заранее разрешается в UFW. После применения настроек мастер просит проверить новое SSH-подключение; если проверка не подтверждена, предусмотрен **автоматический откат через 5 минут**.

**4. Пользователи и sudo** — создание пользователя, установка пароля, назначение sudo. По желанию можно отдельно включить `NOPASSWD` для конкретной учётной записи. Это позволяет выполнять команды от root без ввода пароля — включайте только для доверенных пользователей.

**5. Fail2ban** — защита SSH от перебора паролей, просмотр состояния и логов, разблокировка IP, управление доверенными IP-адресами и подсетями. Настройка SSH jail по умолчанию: 3 неудачные попытки за 30 минут, блокировка на 24 часа.

**6. Система / время** — базовые пакеты, часовой пояс и обновление системы. При выборе часового пояса по умолчанию предлагается `Europe/Moscow`; текущая зона сервера показывается как пример.

**7. Диагностика** — состояние SSH, UFW и Fail2ban, порты и сведения для проверки сервера.

**8. Дополнительные настройки** — необязательная установка Docker Engine и Compose, настройка зеркал и проверка Docker. Docker **не устанавливается** в ходе полной первоначальной настройки.

**9. Перезагрузка сервера** — выводит предупреждение о разрыве SSH-сеанса и запрос `Перезагрузить сервер сейчас? [y/N]`. Перезагрузка запускается только после ответа `y`; Enter или `N` отменяет действие.

## Важное при настройке SSH

- **Не закрывайте текущую SSH-сессию** до подтверждения нового входа. Для проверки открывайте второй терминал.
- После смены SSH-порта входите через новый порт, например `ssh -p 2203 admins@АДРЕС_СЕРВЕРА`. При необходимости учитывайте внешний порт NAT и правила firewall провайдера.
- Перед отключением root убедитесь, что другой пользователь входит по SSH и имеет рабочий `sudo`. При изменении `AllowUsers` проверяйте именно **новое** подключение.
- Для проверки sudo выполните `whoami` и `sudo id -u`. Вторая команда должна вывести `0`.
- На случай потери SSH-доступа полезно иметь доступ к консоли VPS/VNC у хостинг-провайдера.

## Полезные замечания

- При настройке Fail2ban скрипт явно задаёт `allowipv6 = auto` в отдельном файле `/etc/fail2ban/fail2ban.d/90-srv-settings.local`, если глобальный параметр ещё нигде не установлен. Существующие настройки IPv6 не перезаписываются. Проверить SSH-защиту: `sudo fail2ban-client status sshd`.
- Добавленные в исключения Fail2ban доверенные IP не разблокируются задним числом — для этого есть отдельный пункт разблокировки.
- Опубликованные Docker-порты могут обходить обычные правила UFW. Проверяйте ограничения доступа к контейнерам отдельно.
- В интерактивном терминале метка `[WARN]` оранжевая, а текст предупреждения отображается обычным цветом терминала. Отключить цветные метки можно командой `sudo env NO_COLOR=1 bash /opt/srv-settings/setup.sh`.
